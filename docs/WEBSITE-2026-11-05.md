## 1. What this site is

The consulting front door. A visitor should learn three things in the first screen and a half: what
dotBANG builds (AI systems on a company's own data), that it has done it for a real organisation, and
how to start (one DM, no form).

The business model is stated once, in the site's own terms: **the audience is the business; the knowledge
stays free; the paid work is AI systems for companies with data they cannot use; merch and starter kits
are downstream.** That is Tyler's positioning, not a re-derivation. It replaced the old "the knowledge is
free; the merch is the business" line, which inverted the thesis.

## 3. Component system

Consumed from the 2026-11-05 brand pack, not re-authored:

- `assets/base.css` — the pack's `dir06/base.css`, byte-identical.
- `assets/dir06.css` — the pack's `dir-06-refined.css`, byte-identical (type ramp 150/100/66/44, 11px
  label floor, 96/160px rhythm, hairlines). Its `.52s` h1 reveal is retimed to `.24s` in `site.css`,
  not in the vendored file, because the h1 is the LCP element (§7).
- `assets/site.css` — page-level blocks only: inner-page statement, prose, services grid, fact table,
  case header, the accent plate, the ink plate footer. No new colour, radius, gradient or shadow.
- `assets/ratio.css` — **the ratio control**: per-page band mass, every value measured (§6). This is the
  only place page-specific pixel numbers live, and it says so at the top of the file.
- `scripts/inline_css.py` — inlines the five stylesheets into each page and emits the font preloads.
  Sources stay in `assets/`; the pages carry the built block between `inline-css:begin` and
  `inline-css:end`. `--check` fails if a page is stale, and CI runs that check before deploy.

**Brand casing.** The wordmark is written `dotBANG` everywhere; `dir06.css`'s uppercasing treatment is
overridden in `site.css` (dot lowercase, BANG uppercase), and `scripts/smoke_test.py` fails the build on
`DOTBANG` or `DotBang` in any HTML file.

**Type.** Inter and JetBrains Mono, both OFL-1.1 subsets. The pack shipped one byte-identical file under
each weight name (verified by hash), so every weight points at one src per family; the files are then
subset to Latin-1 + general punctuation + arrows, which drops the pair from 79 KiB to 65 KiB and is the
single biggest LCP lever on the site. Regeneration command is in `assets/fonts/fonts.css`.

## 4. Copy deck

The full text is in the HTML. This is the argument each page makes, in order, plus the claims it refuses
to make.

**Home.** Eyebrow `AI systems · built on your data` → `Your data, answered.` → "dotBANG builds the system
that turns a company's own records into the twenty-minute answer a decision-maker needs before a meeting.
Built once, on your data, handed over with the source." → two actions (Start a project / See the work) →
engagement facts (fixed written scope, 8 weeks to version one, pilot at week 5, source handed over) →
`08 / 05 / 20` (weeks, screens, minutes) → three build shapes (territory and sales briefs; data plumbing
and ingestion; local AI and model operations) → case summary and the cluster the work runs on →
`No dashboard without a data proof.` → contact.

**Services.** `Three ways to work with dotBANG.` — the week-one data proof, the eight-week first version
paid per phase, the monthly model-operations retainer. Then what is deliberately *not* in version one
(order entry, commission calculation, forecasting), what dotBANG needs from the client, hosting options,
and payment terms. No prices: Colton owns the number; the page says scope and pricing are agreed per
engagement.

**Work.** Case 001, the Territory Brief, for a national pipe-fittings sales organisation: the ERP is too
slow to open in a truck, so the number a rep walks in with is last month's. What was built: five screens
on 11,232 synthetic rows shaped to their world, territory scoping enforced by role, every number computed
from the ingested rows. How it was verified, and the honest status line: **prototype delivered, version
one in scoping** — not "shipped", not a testimonial.

**Refuses to claim:** no testimonials, no client logos beyond the named organisation, no revenue or "10x"
numbers, no fake store, no invented prize, no placeholder affiliate URLs, no displayed email address, no
analytics.

## 5. Public privacy standard

Enforced, not promised:

- `scripts/privacy-audit.py` fails on any IPv4 address (127.0.0.1 allowed), any email address, and any
  `.local` / `.ts.net` / `.home` hostname in any public file. Currently **PASS**.
- No personal names beyond the brand. The case names the client organisations, not individuals.
- Contact is an Instagram DM link and the public GitHub organisation — no form, no email address in
  public markup, no third-party script, no cookie, no analytics. The footer says so in plain words.
- Footer reads "Utah, United States" and flips to "dotBANG LLC" the day the certificate exists.

## 6. Palette: the ratio is enforced in pixels, and it changed the design

`PALETTE-SPEC-2026-11-05` sets the bands (field 70–80, ink 10–15, accent 4–14, signal ≤1) and the accent
floor at 4% of every delivered surface. The site as it stood measured **black 96.93 / white 3.06 /
accent 0.012** on the home page: the accent was a rounding error, which is exactly Tyler's "no visible
blue" note in pixels.

Reaching the bands required a structural change, not a colour tweak. The site now closes every page with
two plates:

1. **An accent plate** — a filled `#6CACE4` block carrying black type (8.66:1; white type on the accent
   is 2.43:1 and is banned), with a 4px black rule and a black-filled action whose label is the accent.
2. **An ink plate footer** — a white field with black type (21:1): the two contact links, the brand, the
   footer nav, the privacy line.

That is the whole trick: the ratio comes from plate mass, sized per page in `assets/ratio.css`, and the
checker is the judge. One signal element per surface — the 9×9 pink square beside "Available for work"
(P-01, `#F50087`, 5.23:1 on the field). Nothing else is pink.

Measured on the shipped build, every page, both viewports (`audit_palette.py --check`, 14/14 in band):

| page | 1440 field/ink/accent/signal | 390 field/ink/accent/signal |
|---|---|---|
| home | 76.23 / 11.23 / 12.55 / 0.001 | 78.54 / 10.35 / 11.11 / 0.004 |
| services | 75.88 / 11.98 / 12.14 / 0.000 | 78.00 / 12.00 / 9.99 / 0.000 |
| work | 72.60 / 13.70 / 13.70 / 0.000 | 74.71 / 13.21 / 12.08 / 0.000 |
| learn | 78.65 / 10.50 / 10.86 / 0.000 | 75.20 / 13.06 / 11.74 / 0.000 |
| merch | 76.13 / 10.63 / 13.24 / 0.000 | 71.72 / 14.68 / 13.60 / 0.000 |
| giveaways | 78.59 / 10.58 / 10.83 / 0.000 | 74.11 / 13.41 / 12.48 / 0.000 |
| affiliates | 79.65 / 10.24 / 10.11 / 0.000 | 74.35 / 14.52 / 11.13 / 0.000 |

Off-palette pixels: **0.000%** on every surface. The ratio is per delivered page, not per fold — the
stricter reading of the spec, and the one the checker enforces.

## 7. Performance budget, and what the site measured

The budget was declared before the build: performance ≥95 with **LCP ≤1.2s, TBT ≤50ms, CLS ≤0.02, total
transfer ≤500 KiB** on Lighthouse's throttled mobile profile, and no render-blocking resource.

| | before this round | after |
|---|---|---|
| performance (mobile) | 98 | **100** |
| accessibility / best-practices / SEO | 100 / 100 / 100 | **100 / 100 / 100** |
| LCP | 1.95s | **1.20s** |
| FCP | 1.95s | **0.60s** |
| TBT | 0ms | **0ms** |
| CLS | 0 | **0** |
| transfer | 204 KiB | **72 KiB** |
| render-blocking | 1,200ms est. | **0** |

Desktop preset on the same build: performance 100, FCP 0.2s, LCP 0.3s, CLS 0. Services and Work measured
at 100/100/100/100 on mobile as well (same FCP 0.6s / LCP 1.2s / CLS 0).

What produced it, in order of effect: CSS inlined (no render-blocking round trips), fonts deduplicated
and subset, h1 reveal retimed so the LCP element is not held at opacity 0, no JavaScript at all, no
images, no third-party request. The remaining 1.2s LCP on mobile is the throttled font fetch; the HTML
and CSS are already in the first response.

**Honest limit:** LCP 1.20s sits exactly at the declared ceiling. It is met, not beaten. The lever left is
further font subsetting against the actual glyph inventory, which would break if new copy needed a glyph
outside Latin-1 + general punctuation.

## 8. Reproduce every number

```bash
# palette: render every page at both viewports, then run the pack's checker
python3 build/tools/measure.py --tag ship
# -> build/renders/ship/*.png, report.json, and audit_palette.py --check output (14/14 in band)

# performance: serve the built site with gzip (as Pages does) and run Lighthouse
python3 build/tools/serve.py 8791 site &
CHROME_PATH=/home/ty/.cache/ms-playwright/chromium-1248/chrome-linux64/chrome \
  lighthouse http://127.0.0.1:8791/index.html --output=json --output-path=build/lighthouse/home-mobile.json

# repo checks (also run by .github/workflows/pages.yml on every PR and push)
python3 scripts/inline_css.py --check
python3 scripts/privacy-audit.py
PORT=8765 python3 scripts/smoke_test.py
```

The renderer in `build/tools/` is the brand pack's CDP renderer with a private debug port — the pack's
shared port 9444 is used by other lanes, and connecting to someone else's Chromium produces someone
else's screenshot.

## 10. What was not verified

- **Taste.** Every number above is measured; whether two plates is the right voice for the front door is
  Tyler's call, and it is the one thing this build cannot prove.
- **Real devices.** Renders are Chromium 156 at 1440 and 390 in a headless profile. Safari, Firefox and a
  physical phone were not exercised.
- **The domain.** Everything is served from a loopback port; nothing has been through GitHub Pages yet.
